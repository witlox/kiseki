**Cluster:** `default` profile — 6× c3-standard-22-lssd storage (4× NVMe each,
10.3 TB pool) + 3× c3-standard-22 clients, europe-west1-b. EC-4+2, 6-shard
distributed-leader topology (1 leader/node). Rocky 9 binaries from
`perf/2026-05-28-roadmap` **with #137** (chunk-store write parallelism).
64 KB objects. Native/S3 = 3-client parallel, conc 16, 30 s. NFS/FUSE = fio

**Headline:** #137 lifts distributed multi-shard **writes** 6–7× with 0 errors.
The chunk-store write serialization (B7) is gone — `write_chunk` no longer
plateaus under concurrency.

## #137 validation (the point of this run)
- **put-heavy 6.3× / mixed 7.0×** vs the 2026-05-27 baseline, 0 errors.
- Per-phase (separate conc-scaling run, same cluster class): gateway
  `chunk_write` 45 ms → ~12 ms; receiver `write_chunk` 56 ms → **~7 ms, FLAT
  across conc 16→48** (pre-fix plateaued 56→59 ms). The B7 serialization is
  removed.
- raft_commit (consensus) ~7.65 ms — never the bottleneck; the "commit-bound"
  framing was wrong, writes were chunk-store-bound.

## Findings (not #137 regressions — separate follow-ups)
1. **Native conc=48 single-client → ~50% client-side errors** (no server logs,
   `write_chunk` ran for all). The native per-connection in-flight limit;
   48-concurrent **spread over 3 clients** is 0 errors. → native client/protocol
   single-connection concurrency follow-up.
2. **NFSv4.2 read wedges** (D-state) — NFS read path. → follow-up.
3. **FUSE O_DIRECT unsupported** (#37) — blocks clean FUSE throughput
   measurement; functionally correct.
4. **S3 GET 404 on bench-tenant bucket** — IAM write-authz/tenant gotcha (#117),
   pre-existing.
